# Payments API

Crea un pago único por transferencia bancaria y obtén un **CVU/alias** exclusivo para esa orden.

---

## Crear un pago

### Prod

```http
POST https://api.talo.com.ar/payments/
```

### Sandbox

```http
POST https://sandbox-api.talo.com.ar/payments/
```

<Callout type="info">
	Este endpoint es público y no requiere `Authorization` header. El campo `user_id` en el body identifica al comercio.
</Callout>

### Campos requeridos

| Campo            | Tipo       | Descripción                                                     |
| ---------------- | ---------- | --------------------------------------------------------------- |
| `user_id`        | `string`   | ID de tu cuenta Talo (sandbox o producción)                     |
| `price.amount`   | `number`   | Monto del pago (positivo)                                       |
| `price.currency` | `string`   | Moneda. Valores soportados: `"ARS"`, `"BNB"`, `"USDT"`, `"BRL"` |
| `payment_options`| `string[]` | Métodos de pago: `"transfer"`, `"crypto"`, `"pix"`               |

### Campos opcionales

| Campo             | Tipo       | Descripción                                                                                      |
| ----------------- | ---------- | ------------------------------------------------------------------------------------------------ |
| `external_id`     | `string`   | ID único de tu orden en tu sistema                                                                |
| `webhook_url`     | `string`   | URL donde recibirás notificaciones de cambios de estado                                           |
| `redirect_url`    | `string`   | URL a donde redirigir al cliente al terminar el pago                                              |
| `motive`          | `string`   | Motivo del pago                                                                                   |
| `client_data`     | `object`   | Datos del cliente (ver detalle abajo)                                                             |
| `team_id`         | `string`   | ID del equipo (para usuarios con múltiples equipos)                                               |
| `tags`            | `string[]` | Etiquetas para categorizar el pago                                                                |
| `partner_id`      | `string`   | ID del partner que origina el pago (ver nota abajo)                                               |

<Callout type="warning">
	**Partners**: si estás creando pagos en nombre de un comercio como partner, incluí el campo `partner_id` con tu identificador de partner. Esto permite distinguir qué pagos de una cuenta fueron originados por el comercio y cuáles fueron atribuidos al partner.
</Callout>

### Campos de `client_data`

Todos los campos dentro de `client_data` son opcionales:

| Campo        | Tipo     | Descripción                  |
| ------------ | -------- | ---------------------------- |
| `first_name` | `string` | Nombre del cliente           |
| `last_name`  | `string` | Apellido del cliente         |
| `phone`      | `string` | Teléfono del cliente         |
| `email`      | `string` | E-mail del cliente           |
| `dni`        | `string` | DNI del cliente              |
| `cuit`       | `string` | CUIT/CUIL del cliente        |

## Respuesta

```json5
{
	data: {
		id: "VAR-f61876b0-FDF_124", // ID interno de Talo
		payment_status: "PENDING",
		quotes: [
			{
				cvu: "0000630500000060195375",
				alias: "talo.ago.1468",
			},
		],
		payment_url: "https://talo.com.ar/payments/VAR-f618...",
		expiration_timestamp: "2024-09-02T14:00:15.411Z",
	},
}
```

> **Muestra al cliente** el `cvu` o `alias`, o simplemente redirígelo a `payment_url`.

## Estados del pago

| Estado      | Descripción                              |
| ----------- | ---------------------------------------- |
| `PENDING`   | Esperando transferencia                  |
| `SUCCESS`   | Se acreditó el monto exacto             |
| `OVERPAID`  | Se recibió más de lo solicitado          |
| `UNDERPAID` | Se recibió menos de lo solicitado        |
| `EXPIRED`   | El CVU venció (~5 días)                  |

<Callout type="tip">
	Para `OVERPAID` y `UNDERPAID`, decide si aceptas la orden o emites reembolso
	manual.
</Callout>

## Simular pago en sandbox

```http
POST https://sandbox-api.talo.com.ar/cvu/{cvu}/faucet
```

### Parámetros del path

| Campo | Tipo     | Descripción               |
| ----- | -------- | ------------------------- |
| `cvu` | `string` | CVU donde recibir el pago |

### Parámetros del body

| Campo    | Tipo     | Requerido | Descripción              |
| -------- | -------- | --------- | ------------------------ |
| `amount` | `number` | Sí        | Monto a simular en pesos |
| `cuit`   | `string` | No        | CUIT del emisor simulado |

### Ejemplo de simulación

```bash
curl -X POST \
  "https://sandbox-api.talo.com.ar/cvu/0000630500000060195375/faucet" \
  -H "Authorization: Bearer $TALO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "amount": 30000 }'
```

### Payload del webhook:

```json
{
	"message": "Pago Actualizado",
	"paymentId": "VAR-f61876b0-FDF_124",
	"externalId": "ORDER_123"
}
```

## Consultar un pago

```http
GET https://sandbox-api.talo.com.ar/payments/{paymentId}
```

### Parámetros del path

| Campo       | Tipo     | Descripción                 |
| ----------- | -------- | --------------------------- |
| `paymentId` | `string` | ID interno de Talo del pago |

### Campos de la respuesta

| Campo                  | Tipo       | Descripción                                                                             |
| ---------------------- | ---------- | --------------------------------------------------------------------------------------- |
| `payment_status`       | `string`   | Estado del pago                                                                         |
| `payment_url`          | `string`   | URL para completar el pago                                                              |
| `expiration_timestamp` | `string`   | Fecha de vencimiento (ISO 8601)                                                         |
| `quotes[0].address`    | `string`   | CVU para transferir                                                                     |
| `quotes[0].alias`      | `string`   | Alias de la cuenta                                                                      |
| `price.amount`         | `number`   | Monto del pago                                                                          |
| `price.currency`       | `string`   | Moneda                                                                                  |
| `payment_options`      | `string[]` | Métodos de pago                                                                         |
| `external_id`          | `string`   | ID de la orden                                                                          |
| `webhook_url`          | `string`   | URL de webhook                                                                          |
| `redirect_url`         | `string`   | URL de redirección                                                                      |
| `motive`               | `string`   | Motivo del pago                                                                         |
| `transaction_fields`   | `object`   | Campos de la transacción. Presente una vez que se haya realizado el pago.               |
| `transactions`         | `object[]` | Transacciones. Presente una vez que se haya recibido alguna transferencia para el pago. |

```bash
curl -H "Authorization: Bearer $TALO_TOKEN" \
```

## Listar pagos

<Callout type="info">
	Requiere `Authorization: Bearer` header.
</Callout>

### Query parameters

| Campo                        | Tipo     | Requerido | Descripción                                                                                   |
| ---------------------------- | -------- | --------- | ----------------------------------------------------------------------------------------------|
| `user_id`                    | `string` | Sí        | ID del usuario cuyos pagos se quieren consultar                                               |
| `team_id`                    | `string` | No        | Filtrar por equipo                                                                             |

| `end_date`                   | `string` | No        | Fecha de fin (ISO 8601)                                                                        |

## Actualizar expiración del pago

```http
PUT https://sandbox-api.talo.com.ar/payments/{payment_id}/expiration
```

Permite extender la fecha de expiración de un pago en estado `PENDING`.

### Parámetros del path

| Campo        | Tipo     | Descripción                 |
| ------------ | -------- | --------------------------- |
| `payment_id` | `string` | ID interno de Talo del pago |

### Campos requeridos

| Campo                  | Tipo     | Descripción                              |
| ---------------------- | -------- | ---------------------------------------- |
| `expiration_timestamp` | `string` | Nueva fecha de expiración (ISO 8601)     |

### Ejemplo

```bash
curl -X PUT https://sandbox-api.talo.com.ar/payments/VAR-f61876b0-FDF_124/expiration \
  -H "Authorization: Bearer $TALO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "expiration_timestamp": "2024-09-10T14:00:00.000Z"
  }'
```

<Callout type="warning">
	**Respuesta real (verificado en sandbox)**: este endpoint **no** usa el envelope `{message, error, code, data}` del resto de la API — devuelve directamente el objeto payment actualizado, con HTTP 200.
</Callout>

## Actualizar precio del pago

```http
PUT https://sandbox-api.talo.com.ar/payments/{paymentId}/price
```

Permite actualizar el precio de un pago. Si el pago está en estado `SUCCESS`, `OVERPAID` o `UNDERPAID`, se recalculará el estado basado en el nuevo precio y se enviará una notificación al webhook configurado.

### Parámetros del path

| Campo       | Tipo     | Descripción                 |
| ----------- | -------- | --------------------------- |
| `paymentId` | `string` | ID interno de Talo del pago |

### Campos requeridos

| Campo      | Tipo     | Descripción                                           |
| ---------- | -------- | ----------------------------------------------------- |
| `currency` | `string` | Código de moneda (`"ARS"`)                            |
| `amount`   | `number` | Nuevo monto del pago                                  |

<Callout type="warning">
	No se puede actualizar el precio de un pago en estado `EXPIRED`.
</Callout>

### Ejemplo

<Tabs items={['cURL','Node.js']}>
  <Tab label="cURL">

```bash
curl -X PUT https://sandbox-api.talo.com.ar/payments/VAR-f61876b0-FDF_124/price \
  -H "Authorization: Bearer $TALO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "currency": "ARS",
    "amount": 35000
  }'
```

  </Tab>
  <Tab label="Node.js">


## Actualizar metadatos del pago

Permite modificar campos específicos del pago con seguimiento de historial.

### Prod

```http
PUT https://api.talo.com.ar/payments/{paymentId}/metadata
```

### Sandbox

```http
PUT https://sandbox-api.talo.com.ar/payments/{paymentId}/metadata
```

### Parámetros del path

| Campo       | Tipo     | Descripción                 |
| ----------- | -------- | --------------------------- |
| `paymentId` | `string` | ID interno de Talo del pago |

### Campos requeridos

| Campo    | Tipo     | Descripción     |
| -------- | -------- | --------------- |
| `motive` | `string` | Motivo del pago |

### Ejemplo de solicitud

<Tabs items={['cURL','Node.js']}>
  <Tab label="cURL">

```bash
curl -X PUT https://sandbox-api.talo.com.ar/payments/VAR-f61876b0-FDF_124/metadata \
  -H "Authorization: Bearer $TALO_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "motive": "Compra de productos - actualizado"
  }'
```

  </Tab>
  <Tab label="Node.js">

```js
await fetch("https://sandbox-api.talo.com.ar/payments/VAR-f61876b0-FDF_124/metadata", {
	method: "PUT",
	headers: {
		Authorization: `Bearer ${process.env.TALO_TOKEN}`,
		"Content-Type": "application/json",
	},
	body: JSON.stringify({
		motive: "Compra de productos - actualizado",
	}),
})
```

  </Tab>
</Tabs>

### Respuesta real (verificado en sandbox)

<Callout type="warning">
	**Comportamiento real verificado (sandbox, 2026-07-15)**: la respuesta es **HTTP 200 con body `null`**, no el envelope `{message, error, code, data}` de abajo. El cambio **sí se aplica** (confirmado con un `GET /payments/{paymentId}` inmediatamente después — el `motive` y el historial en `metadata.motive[]` quedan actualizados), pero la respuesta del PUT no lo confirma. **Recomendación**: no confíes en el body de este PUT — hacé un `GET /payments/{paymentId}` después para confirmar que el cambio se aplicó.
</Callout>

```json
null
```

HTTP status: `200`

El shape de abajo (`{message, error, code, data}`) es el que la API está *diseñada* para devolver, y podría volver a funcionar si se corrige el bug de backend — pero hoy no es lo que se recibe:

```json
{
	"message": "Metadata updated successfully",
	"error": false,
	"code": 200,
	"data": {
		"motive": "Compra de productos - actualizado",
		"metadata": {
			"motive": [
				{
					"value": "Compra de productos - actualizado",
					"previous": "Compra de productos",
					"modified_by": "user@example.com",
					"modification_timestamp": "2024-09-02T15:30:45.123Z"
				}
			]
		}
	}
}
```

### Funcionalidad

- **Historial de cambios**: Cada modificación se registra con el valor anterior, nuevo valor, usuario que realizó el cambio y timestamp
- **Validación de permisos**: Solo el propietario del pago puede modificar los metadatos
- **Campos disponibles**: Actualmente solo se permite modificar el campo `motive`
- **Confirmá con un GET**: dado que el PUT no devuelve confirmación fiable, hacé `GET /payments/{paymentId}` después de cada actualización de metadata para verificar que se aplicó

<Callout type="warning">
	Los cambios de metadatos quedan registrados permanentemente en el historial del pago.
</Callout>
