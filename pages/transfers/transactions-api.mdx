# Transactions API

Consulta las transacciones de tu cuenta. Cada vez que se recibe una transferencia bancaria (ya sea por un pago único o un cliente fijo), se genera una transacción.

---

## Listar transacciones

```http
GET https://api.talo.com.ar/transactions/
```

### Sandbox

```http
GET https://sandbox-api.talo.com.ar/transactions/
```

<Callout type="info">
	Requiere `Authorization: Bearer` header.
</Callout>

### Query parameters

| Campo                        | Tipo     | Requerido | Descripción                                          |
| ---------------------------- | -------- | --------- | ---------------------------------------------------- |
| `user_id`                    | `string` | Sí        | ID del usuario cuyas transacciones se quieren listar  |
| `team_id`                    | `string` | No        | Filtrar por equipo                                    |
| `limit`                      | `string` | No        | Cantidad de resultados por página (numérico)          |
| `start_date`                 | `string` | No        | Fecha de inicio (ISO 8601)                            |
| `end_date`                   | `string` | No        | Fecha de fin (ISO 8601)                               |
| `cursor_user_id`             | `string` | No        | User ID del cursor para paginación                    |
| `cursor_transaction_id`      | `string` | No        | Transaction ID del cursor para paginación             |
| `cursor_creation_timestamp`  | `string` | No        | Timestamp del cursor para paginación                  |

<Callout type="tip">
	Para paginar, usa los valores `cursor_user_id`, `cursor_transaction_id` y `cursor_creation_timestamp` del campo `lastEvaluatedKey` de la respuesta anterior. A diferencia de `GET /payments/`, en este endpoint **`limit` sí se respeta y la paginación con `lastEvaluatedKey` funciona** — verificado en sandbox pidiendo `limit=3` sobre una cuenta con más movimientos y encadenando dos páginas con el cursor de salida.
</Callout>

<Callout type="warning">
	**`transaction_id` viene con prefijo `TX#`** (ej. `TX#87723204-ba9e-4e70-afba-da165eac4a32`), no como UUID limpio. Además, cada item trae un campo `id` adicional (no documentado antes) con el mismo UUID **sin** el prefijo. Si necesitás el UUID limpio para otra llamada, usá `id`, no `transaction_id`.
</Callout>

### Ejemplo

```bash
curl -H "Authorization: Bearer $TALO_TOKEN" \
  "https://sandbox-api.talo.com.ar/transactions/?user_id=f61876b0-10a5-4e39-8e2c-17343b3fa1b6&limit=10"
```

## Consultar una transacción

```http
GET https://api.talo.com.ar/transactions/{transaction_id}
```

### Sandbox

```http
GET https://sandbox-api.talo.com.ar/transactions/{transaction_id}
```

<Callout type="error">
	**Known issue (backend) — verificado en sandbox el 2026-07-15**: este endpoint devuelve **`403 Forbidden`** (`{"message":"Forbidden"}`) para tokens de merchant con rol `owner` (el token estándar que devuelve `POST /users/{user_id}/tokens`), incluso siendo el dueño de la transacción consultada. Se probó con el UUID real, con el UUID prefijado `TX#` (URL-encoded) y con un id inexistente: siempre 403. Sin header `Authorization` la API responde `401 Unauthorized` (o sea, el authorizer corre igual), así que no es un problema de token inválido ni de formato de id.

	**Causa raíz identificada en el código**: `auth_api_sls/src/privileges.ts`, dentro de `[transactionsAPI]`, la entrada `"/{transaction_id}": { GET: [PrivateRole.YODA, PrivateRole.R2D2] }` sólo habilita roles internos. La entrada hermana `"/"` (listar transacciones) sí incluye `PublicRole.OWNER`, `PublicRole.SUPERVISOR`, etc. Es decir, **a este endpoint le falta agregar `PublicRole.OWNER` (y probablemente `PublicRole.SUPERVISOR`/`SUPERVISOR_JR`) a la lista de roles permitidos** — luce como un endpoint que quedó registrado como interno-only por error, mientras el resto de la Transactions API sí es consumible por merchants.

	**Workaround mientras no se corrija**: usá `GET /transactions/?user_id=...` (que sí funciona) y filtrá client-side por `transaction_id` (recordá el prefijo `TX#` — ver sección anterior) o por `id`. Esa respuesta ya incluye todos los campos de detalle de la transacción.
</Callout>

### Parámetros del path

| Campo            | Tipo     | Descripción                    |
| ---------------- | -------- | ------------------------------ |
| `transaction_id` | `string` | ID de la transacción           |

### Query parameters

| Campo     | Tipo     | Requerido | Descripción         |
| --------- | -------- | --------- | ------------------- |
| `user_id` | `string` | Sí        | ID del usuario dueño de la transacción |

## Campos de la transacción

| Campo                | Tipo       | Descripción                                                    |
| -------------------- | ---------- | -------------------------------------------------------------- |
| `transaction_id`     | `string`   | ID único de la transacción                                     |
| `user_id`            | `string`   | ID del usuario dueño                                           |
| `transactionType`    | `string`   | Tipo: `INBOUND`, `OUTBOUND`, `REFUND`                          |
| `amount`             | `string`   | Monto neto de la transacción                                   |
| `gross_amount`       | `string`   | Monto bruto recibido                                           |
| `address`            | `string`   | CVU receptor                                                   |
| `address_alias`      | `string`   | Alias receptor                                                 |
| `currency`           | `string`   | Moneda de la transacción                                       |
| `network`            | `string`   | Red de procesamiento                                           |
| `commission`         | `number`   | Porcentaje de comisión                                         |
| `commission_amount`  | `string`   | Monto de la comisión                                           |
| `taxes`              | `array`    | Impuestos aplicados (`tax_type`, `tax_rate`, `tax_amount`)     |
| `transaction_status` | `string`   | Estado: `PROCESSED`                                            |
| `transaction_data`   | `object`   | Datos del procesamiento bancario                               |
| `payment_id`         | `string`   | ID del pago asociado (si aplica)                               |
| `customer_id`        | `string`   | ID del cliente asociado (si aplica)                            |
| `creation_timestamp` | `string`   | Fecha de creación (ISO 8601)                                   |
